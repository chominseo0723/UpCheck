# 개인정보와 권한 범위

## 전송하는 내용

앱은 등록된 안내문과 제출자의 PDF **원문**을 Upstage에 업로드해 문서 유형, 작성자, 접수번호, 누락·중복을 대조합니다. 업로드 전에 이름·서명·연락처를 지우는 익명화 기능은 구현되어 있지 않습니다. PDF에 포함된 개인정보도 전송 범위에 들어갈 수 있습니다.

AI에게 출력 항목을 최소화하도록 지시하지만, 이 지시가 원문 전송이나 외부 서비스의 보관을 없애는 것은 아닙니다. AI 제공자의 무학습, 무보관, 즉시 삭제를 이 코드만으로 보장하지 않습니다.

## 화면과 메일

- 관리자 화면의 상세 JSON에는 작성자 이름이 남을 수 있습니다. 운영 화면을 촬영·공개할 때는 실제 개인정보를 가려야 합니다.
- 보완 안내 메일의 문서 작성자 이름은 일부 가립니다. 예: `박지민 → 박*민`.
- 안내 메일에 원문 PDF, 연락처, 서명 이미지를 다시 첨부하지 않습니다.
- 화면과 HTML 메일의 동적 텍스트는 이스케이프합니다.
- 확정된 누락·중복만 원 제출자에게 회신합니다. 발신자와 Reply-To가 다르거나 자동 생성된 메일은 자동 회신하지 않습니다.

이름 일부 가림은 안내 출력의 최소화입니다. 원문 PDF의 익명화와 같은 의미가 아닙니다.

## 계정별 분리와 API 키

- 접속 사용자 권한으로 실행하는 Apps Script 배포를 전제로 합니다.
- 관리자 수신 주소가 로그인한 Google 계정과 일치해야 합니다.
- `UserProperties`와 `UserLock`을 사용해 계정별 설정·API 키·접수 기록·실행 잠금을 분리합니다.
- API 키는 웹앱의 비밀 입력란에서 등록하고, 화면에는 끝 4자리만 표시합니다. 서버 오류의 키 형태 문자열은 가려서 표시합니다.
- UserProperties는 자체 암호화 금고나 프로젝트 편집자 접근 차단을 보장하는 수단이 아닙니다. Apps Script 프로젝트 편집자와 운영 권한도 제한해야 합니다.
- 저장소에는 실제 API 키, OAuth 토큰, 받은편지함 원문과 실제 접수 로그를 넣지 않습니다.

코드의 제목 조건은 **`[서류체크 실험]`**입니다. OAuth에서 Gmail 권한 자체가 해당 제목으로만 제한되는 구조는 아닙니다. 앱 내부 필터와 Google 권한 범위를 구분해야 합니다.

## 보관과 삭제

| 위치 | 처리·보관 범위 |
| --- | --- |
| Gmail | 원래 메일·첨부·자동 회신과 Gmail 정책 |
| Apps Script UserProperties | 관리자 설정, API 키, 메시지 ID·상태·AI 결과·미리보기 등 |
| Upstage | 업로드 원문, 실행 입력·결과 등 해당 서비스 처리 범위 |

이 버전에는 전체 접수·키·외부 업로드의 통합 자동 삭제나 보유기간 만료 삭제 기능이 없습니다. 운영자는 각 서비스의 실제 보관·삭제 정책과 기관 기준을 확인하고 삭제 절차를 마련해야 합니다. **중지**는 자동 점검을 끄는 기능이며 기존 데이터 삭제나 Google 권한 철회가 아닙니다.

## 처리 근거와 운영 범위

화면의 처리 안내 확인은 관리자가 원문 AI 전송 범위를 읽었다는 확인입니다. 제출자의 유효한 동의나 기관의 적법한 처리 근거 확인을 대신하지 않습니다. 실제 기관에 적용하기 전에 처리 목적, 필요한 항목, 외부 위탁·전송, 보관기간, 접근권한과 삭제 절차를 기관 기준에 맞게 확인해야 합니다.

가상 예제는 이름·학번·연락처·서명이 모두 실험용 값입니다. 원래 학교 서식의 일반 개인정보 문구가 남아 있어도, 그것이 UpCheck의 실제 법적 근거나 보관 정책을 의미하지 않습니다.

외부 계정의 미검증 앱 경고와 검증 절차는 [Google 공식 문서](https://developers.google.com/apps-script/guides/client-verification)를 참고하세요.
